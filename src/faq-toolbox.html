Toolbox: why is a value marked "typical – unverified"?

Only the flow limits (±20%) and the 120 s flow-fault delay are stated in the ModuLaser Install Manual (Table 29, p.76). Fire 1 starts at the class FM/UL hole-sensitivity limit (App. A, printed p.113: VEWFD <1.00, EWFD <1.50, SFD <2.50 %obs/ft), which is a hole limit, not an alarm default. The manual sets alarm thresholds through ClassiFire factors (Table 24, p.71: Alert 10, Prealarm 6, Alarm 8; Alarm 2 absolute 20, units not stated). VEWFD Alert 0.2 %obs/ft is per NFPA 76, as summarized in Honeywell ASAG44201 Table 1. Everything else is a typical starting point until a citation is added — verify before handoff.

Toolbox: will a Battery Calculator project give the same answer here?

Yes. Both apps embed the same MASD engine and parser; an automated parity test runs the same real .pl scenarios through both and compares every result.

Toolbox: what happens to my old calculator files?

Use File → Import legacy calc / Excel…. Nothing in the old file is changed; the migration report lists anything that didn't map. Then Export project to get a .mlproj.json.

Toolbox: why is 00.01.000 not 01.00.000?

00.01.000 is a pre-release. 01.00.000 is reserved for the refined first release.

Toolbox: what about metric PipeCAD files?

Lengths and coordinates are converted to feet. The hole-sensitivity unit in metric files is not yet confirmed, so a warning is shown and values are left as PipeCAD wrote them.

Toolbox: why can't I export the project?

Performance Criteria are not complete. Config validation lists what is missing: a blank or unconfirmed limit, a missing reference, or the narrative not yet confirmed by the engineer. UL market projects only need the narrative confirmed.

Toolbox: why is SFD 2.18 and not 2.50?

For the UL market the UL least-sensitive limit (2.18 %obs/ft for SFD/OAP) applies. 2.50 is the FM hole limit (App. A, printed p.113), used only when FM is the basis.
