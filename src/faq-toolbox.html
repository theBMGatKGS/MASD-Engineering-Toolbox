Toolbox: why is a value marked "typical – unverified"?

Only the flow limits (±20%) and the 120 s flow-fault delay are stated in the ModuLaser Install Manual (Table 29, p.76). Fire 1 starts at the class FM/UL hole-sensitivity limit (App. A, printed p.113: VEWFD <1.00, EWFD <1.50, SFD <2.50 %obs/ft), which is a hole limit, not an alarm default. The manual sets alarm thresholds through ClassiFire factors (Table 24, p.71: Alert 10, Prealarm 6, Alarm 8; Alarm 2 absolute 20, units not stated). VEWFD Alert 0.2 %obs/ft is per NFPA 76-2024 8.5.3.1.2.5 (VEWFD Alert 0.2 / Alarm 1.0 %/ft = 0.65 / 3.2 %/m, effective at each port, above ambient). Everything else is a typical starting point until a citation is added — verify before handoff.

Yes. Both apps embed the same MASD engine and parser; an automated parity test runs the same real .pl scenarios through both and compares every result.

Toolbox: what happens to my old calculator files?

Use File → Import legacy calc / Excel…. Nothing in the old file is changed; the migration report lists anything that didn't map. Then Export project to get a .mlproj.json.

Toolbox: why is 00.01.000 not 01.00.000?

00.01.000 is a pre-release. 01.00.000 is reserved for the refined first release.

Toolbox: what about metric PipeCAD files?

Lengths and coordinates are converted to feet. The hole-sensitivity unit in metric files is not yet confirmed, so a warning is shown and values are left as PipeCAD wrote them.

Toolbox: why can't I export the project?

Performance Criteria are not complete. Config validation lists what is missing: a blank or unconfirmed limit, a missing reference, or the narrative not yet confirmed by the engineer. NFPA presets fix the UL limits, so they only need the code prescriptions and the narrative confirmed.

Toolbox: why is SFD 2.18 and not 2.50?

With an NFPA preset (e.g. SFD/OAP – NFPA 72) the UL 268, 7th Ed. Open Area limit, 2.18 %obs/ft for SFD/OAP (transport no more than 43 s), applies (Install Manual App. A, printed p.113). 2.50 is the FM hole limit (App. A, printed p.113), used only with an FM preset (SFD – FM DS 5-48).

Toolbox: what does "engineer to define" mean?

No cited source for that value is on file, so nothing was filled in. Enter the value, record its reference (code and section or document) and tick Confirmed. FM DS 5-32 / 5-48 and NFPA 76/318/72 ASD criteria are being researched; cited values will be prefilled in a later revision.

Toolbox: why do the British Standards presets match the Battery Calculator?

They are the same BS 5839-1 options as the calculator's Design Basis drop-down, so one project uses one set of names.

Toolbox: why is EWFD transport 43 s and not 90 s?

For NFPA presets the UL 268, 7th Ed. Special Application Range 2 applies (≤43 s, App. A printed p.113). NFPA 76-2024 8.5.3.2.1.4 alone allows 90 s, but UL governs for the NFPA presets. 90 s is also the FM Class 3230 value, used with FM presets. The EWFD 1.5 %/ft (5.0 %/m) alarm limit comes from NFPA 76-2024 8.5.3.2.1.3.

Toolbox: why doesn't "Complies with UL 268" print?

The engineer must tick the UL 268, 7th Edition confirmation in Performance Criteria. It is never confirmed automatically; until then the printout says compliance is not yet confirmed and Export project is blocked.

Toolbox: who can approve field changes, and in what order?

Technician (signs in the Commissioning Report) → designer (verifies or rejects each change in the Toolbox) → QA/Auditor (approves). Each needs a real name, QA must differ from the designer, status is set only by these actions, reopening keeps the history, and a QA override of unconfirmed PipeCAD changes needs a reason and is logged.

Toolbox: where do the EWFD 0.5 and SFD 1.0 Alert values come from?

They are a site/design choice with no code basis, so they are never prefilled as cited and stay marked for confirmation. The VEWFD Alert 0.2 %/ft is NFPA 76-2024 8.5.3.1.2.5.
