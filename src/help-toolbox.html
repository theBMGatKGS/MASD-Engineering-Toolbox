How to use the Toolbox

Modes: Config, Calculator, Both

The switch in the quick row (and View → Mode) sets what this project shows. Config: device configuration only. Calculator: the Battery Calculator exactly as in Battery Calculator 02.00.002. Both: Config and Battery calc tabs. The mode is saved in the project file (design.toolbox.mode) and can be changed at any time; no data is removed when you switch.

Config (design) mode

Every detector and display from the calculator sheets (or from Import .pl (config)… without sheets) is listed by Area/Group. Select one and Seed from class: values come from the performance class (VEWFD/EWFD/SFD from the PipeCAD transit class). Edit Alert, Prealarm (ModuLaser has no "Action" level), Fire 1, Fire 2 (absolute), Prealarm and Fire 1 delays, cascading, latching alarms/faults, flow-fault limits and delay, day/night, LDD, the IN1/IN2/OUT1–OUT3 I/O assignments with FACU addresses, and display role/buzzer. Badges show where each value came from: manual (stated in the ModuLaser Install Manual 04-4001-501-0803-05: flow ±20% and 120 s flow-fault delay, Table 29 p.76), typical – unverified (a starting point with no manual citation yet — verify it), design (set by you). Hover a field label for its citation. Validation: rising levels, ranges (delays 0–90 s, Table 26 p.73), FACU address format and duplicates, 16-character names, and a warning when Fire 1 is not below the class hole-sensitivity limit (App. A, printed p.113). Export project writes the configuration into each device (design.devices[].config); the Commissioning Report uses it instead of its placeholder defaults, and values still marked typical stay flagged there.

Legacy imports

File → Import legacy calc / Excel… reads every Battery Calculator format found in its history: Save As .html from 01.04 to 02.00 (embedded state), a state .json / localStorage dump, and Excel exports (01.04–01.06 per-sheet workbooks and the 02.00.000 CAD Schedule/Detail workbook). The file is migrated to the current state, re-calculated with the current engine, and a migration report lists every field that did not map, every field filled with a current default, and old vs new required Ah per sheet. The report is saved in design.migration; File → Export project writes the .mlproj.json. Excel exports hold displayed values only, so wiring/battery choices are re-derived and listed.

Field-change loop and approvals

On site, the Commissioning Report (02.00.001+) logs each change to a design value — field, old/new, who, when, why, photo — and the technician signs. Import the returned project here and open Field changes: Verify & apply writes the change into the design (name, address, fan speed, configuration, I/O) and re-runs the battery calculation; Reject records a reason. Changes that PipeCAD must also carry (fan speed, Alarm Factor, name, transport, holes, class) go on the PipeCAD change list; importing the updated .pl verifies them automatically (match / mismatch / not found). QA/Auditor approves all verified changes. Order is enforced: the technician signs first (in the Report), then the designer verifies or rejects every change, then QA approves. Status is set only by these actions (never by hand); each role needs a real name and QA must differ from the designer; Reopen asks why and keeps the previous verification in the change history; approving PipeCAD changes not yet confirmed in a .pl needs an override reason, which is logged in the approval history. Names, dates and statuses for technician → designer → QA are stored in doc.approvals.

Toolbox reports

View → Toolbox reports…: Configuration schedule, Field Change / As-Built, PipeCAD change list and Migration report, each as Print/PDF, HTML, Word or Excel. The battery reports stay in File → Print / Export.

Shared engine and harmonization

The Toolbox and the Battery Calculator run the byte-identical MASD engine (Help → Revision Log → Calculation engine) and the same .pl parser. Harmonization rule: any engine change bumps both apps' revisions with matching notes, and each app records the engine version. The shared project-file module (modulaser-project.js) is identical in the Toolbox, the calculator and the Commissioning Report.

Performance Criteria

Config → Performance Criteria is set per project (optional per-Area/Group overrides) and carried in .mlproj.json, the Toolbox Configuration schedule and the Commissioning Report summary page. Pick the Referenced standard:

  • VEWFD – NFPA 76/318, EWFD – NFPA 76, SFD/OAP – NFPA 72 (default): UL 268, 7th Ed. thresholds apply — hole sensitivity at or below (≤) VEWFD 1.0 / EWFD 1.5 / SFD-OAP 2.18 %obs/ft and transport time no more than 60 / 43 / 43 s (UL 268, 7th Ed. Special Application Range 1 / Special Application Range 2 / Open Area per ModuLaser Install Manual App. A, printed p.113; EWFD 1.5 %obs/ft from NFPA 76) — plus the selected code's prescriptions. The engineer must tick the UL 268 confirmation before printouts state "Complies with UL 268, 7th Edition"; it is never confirmed automatically.
  • EWFD – FM DS 5-32, SFD – FM DS 5-48: FM requirements only (not UL, no UL 268 statement). Hole limits prefilled from FM Class 3230 per the Install Manual App. A, printed p.113 (SFD 2.50); confirm them.
  • BS 5839-1 Category M/L, M/L + Generator, P (Staffed), P (Unstaffed) — the same British Standards options as the Battery Calculator's Design Basis — and Custom: no cited values on file, so every value is engineer to define.

Selecting any NFPA preset carries a UL 268, 7th Edition claim (printed only after the engineer confirms it). Thresholds recorded per Brent (2026-10-13): VEWFD <1.0 %obs/ft, ≤60 s (UL 268 Special Application Range 1); EWFD <1.5 %obs/ft from NFPA 76-2024 8.5.3.2.1.3 with the UL 268 Range 2 transport limit ≤43 s (Range 2 itself spans 0.05–2.18 %obs/ft, 3–43 s); SFD/OAP <2.18 %obs/ft, ≤43 s (UL 268 Open Area 1.70–2.18 %obs/ft, 6–43 s) — Install Manual App. A, printed p.113. The cleanroom/semiconductor path under VEWFD – NFPA 76/318 cites NFPA 318-2025 §11.1.3 (return-airstream detection per NFPA 72; life-safety or property-protection designation; 200 ft² per port below the waffle floor and 4.3 ft² at the return-air entry; alert 0.2 / alarm 1.0 %/ft at the port; transport ≤60 s). NFPA 318 does not use the VEWFD/EWFD terms.

Sensitivity pass rule (Brent, 2026-10-13): a sampling hole passes when its sensitivity is at or below (≤) the class maximum, taking the more restrictive of UL and NFPA (VEWFD 1.00, EWFD 1.50, SFD 2.18 %obs/ft); transport time ≤ (60 / 43 / 43 s). Design Target values are shown for each class: VEWFD 1.0, EWFD 1.5, SFD 2.0 %obs/ft. On UL projects the ModuLaser UL 268 range is also shown and its lower limit is enforced (Install Manual App. A, printed p.113): VEWFD Special Application Range 1 0.05–1.00 %obs/ft, 3–60 s; EWFD Range 2 0.05–2.18 (max 1.5 per NFPA 76), 3–43 s; SFD Open Area 1.70–2.18, 6–43 s.

Only values with a cited source are prefilled (marked cited prefill). Blank values are marked engineer to define; enter each one with its reference and tick Confirmed. Code prescriptions are listed per standard the same way. The narrative is auto-drafted from the selections and names the referenced standard; edit it, then tick Narrative confirmed. Record the Engineer of Record and specification reference. Anything undefined or unconfirmed blocks Export project.

Toolbox menu items

File → Migration report… re-opens the last legacy-import migration report. Edit → Field changes… opens the field-change loop (verify, apply, reject, approve). Edit → PipeCAD change list… lists changes PipeCAD must carry. View → Mode: Config only, Mode: Calculator only and Mode: Both switch the project mode (stored per project).
