MASD Engineering Toolbox — Quick Start

From PipeCAD design to approved as-built: configure, size batteries, hand off, log site changes, verify and approve.

1 · PipeCAD designer

Name Floors as Areas/Groups. Keep detector names ≤16 characters including spaces (display limit). Set display type (Standard/Minimum/Command = partNumber 0/1/2). Place PSU and Battery objects where they will be mounted. Set aspirator speed and transit-time class (60/90/120 s = VEWFD/EWFD/SFD). Run the calculation, then export the .pl — addresses export as 0, that is expected.

2 · Toolbox — Config

Pick the mode (Config, Calculator or Both; saved per project). Import .pl. An ASD-160 gets Remote configuration levels (Aux < Pre-Alarm < Fire < Fire 2) from the Alarm Factor worksheet; Fire 2 must be 0.00914–7.62 %obs/ft. Each detector and display gets Alert/Prealarm/Fire 1/Fire 2, delays, latching, flow-fault limits and delay, day/night, LDD, I/O assignments and display settings, seeded from the performance class. Badges: manual = stated in the ModuLaser Install Manual (flow ±20% and 120 s flow-fault delay, Table 29 p.76); typical – unverified = must be checked; design = set by you. Then set Performance Criteria: pick the Referenced standard. NFPA presets (VEWFD – NFPA 76/318, EWFD – NFPA 76, SFD/OAP – NFPA 72) apply UL 268, 7th Ed. thresholds (sensitivity < VEWFD 1.0 / EWFD 1.5 / SFD-OAP 2.18 %obs/ft; transport ≤ 60 / 43 / 43 s; App. A p.113) — confirm UL 268 compliance before it prints; FM DS 5-32 / 5-48 are FM only; BS 5839-1 and Custom are engineer to define. Fill, reference and confirm every blank value, confirm the narrative, enter the Engineer of Record and spec reference — Export project is blocked until done.

3 · Toolbox — Battery calc

Same engine as the Battery Calculator 02.02.000 (MASD engine 1.2.0). Pick the brand (Edwards | Kidde Commercial), set battery factors and the supply variant. Max 4 AUX circuits per power supply; each ribbon run holds max 4 detectors + 1 display (a run started by a detector counts it); a cluster may use any number of runs; modules on their own AUX are not runs; 65 Ah limit; never share a PSU across Areas/Groups. ASD-160s (Micra25) get their own AUX circuit and, when networked, count toward the 127-module SenseNET limit. File → Export project writes the .mlproj.json. Old calculator files and Excel exports: File → Import legacy calc / Excel… (migration report shows anything that did not map).

4 · Commissioning Report

Import project: devices, PSUs, batteries, addresses, pipe data and your configuration values arrive prefilled (typical values stay flagged). Every site change to a design value is logged — field, old/new, who, when, why, photo. Technician signs; print the Field Change / As-Built report; export the project back.

5 · Toolbox — Verify & close

Import the returned project, open Field changes: Verify & apply or Reject each change; the battery calc re-runs. Print the PipeCAD change list, update PipeCAD, import the new .pl — matching changes verify automatically. QA/Auditor approves; name, date and status are stored in the file.

Do

  • Name Floors as Areas/Groups; keep names ≤16 characters
  • Verify every typical – unverified value before handoff
  • Send the .mlproj.json and the .pl together
  • Re-import the updated .pl after PipeCAD changes

Don't

  • Share a PSU across Areas/Groups
  • Exceed 4 AUX per PSU, 4 detectors + 1 display per ribbon run, or 65 Ah
  • Edit addresses in PipeCAD (set them in the Toolbox)
  • Approve as QA with PipeCAD changes still pending .pl

Checklist before sign-off

  • ☐ Mode chosen for the project
  • ☐ Every device configured, no red errors
  • ☐ Typical values verified
  • ☐ PSUs assigned, addresses set, all PASS
  • ☐ .mlproj.json exported with the .pl
  • ☐ Field changes verified / rejected
  • ☐ PipeCAD change list closed by new .pl
  • ☐ QA approval recorded
